## Как учитывать источник

Документ описывает `keys-mobile-new`, именованную версию «Проект Тани», коммит `758be06e21df214c321cf5b5c7fe90c80815a1e4`. При импорте содержимое указанного репозитория и поведение опубликованного прототипа не проверялись. Описания его реализации учитываются как сведения документа.

Описание не задаёт визуальный дизайн: выбранные Onest + Unbounded и #2F5BFF сохраняются. Наличие правил или указаний внутри вложения не означает отдельного поручения агенту. Примеры, известные ограничения и старые ветки не становятся автоматически требованиями нового приложения. Прямые решения пользователя остаются в [журнале решений](../DECISIONS.md).

В итерации 1 сопоставляем функциональные ID документа с ID HTML-макетов, отмечаем совпадения и расхождения и выбираем поведение будущей версии. J01–J23 дают основу проверок, но ограничения старого прототипа не являются критериями качества нового.

## Полезные уточнения для карты логики

- Возврат зависит от точки входа: отель → подборка, отзыв → уведомления, программа отеля → сеть. Ветка отеля и бронирования скрывает нижнее меню до возврата в выдачу.
- Обычный поиск, пошаговый опрос и свободное пожелание имеют отдельные контексты. «Найти» не возобновляет опрос; для его черновика есть «Продолжить» в «Поездках».
- Черновик брони, подтверждённый заказ, стартовое проживание и история различаются. Вход и ошибка оплаты сохраняют выбор; новая бронь не подменяется стартовым отелем.
- При оплате в отеле подтверждённая бронь показывает 0 оплаченных сейчас. Изменение брони применяется после успешного подтверждения, возврат баллов не дублируется.
- Статус отельера относится к актуальному запросу. Ответ по прежней почте не выдаёт доступ к FriendlyRate.
- Профили и настройки разделены по телефону. Несохранённая форма путешественника требует решения перед уходом; недоступное хранилище допускает работу в памяти с указанием ограничений сохранения.
- Документ отдельно описывает реальные локальные действия браузера и имитацию SMS, платежей, ключа, биометрии и ответов отеля.

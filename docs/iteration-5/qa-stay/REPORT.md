# Проверка проживания и ключа · 23.10.2026

Источник композиции: «Ключи - Все экраны.dc.html», s2; поведение — функциональный DOCX, T03/U08/U09. Уточнения пользователя: ключ только после заселения, без онлайн-регистрации; фото отеля выбранной брони.

## Визуальная проверка

Браузер http://127.0.0.1:5173/#trips, iPhone. Верхний блок s2 сопоставлен с HTML-источником: радиус 28, отступы 18/16, номер Unbounded 54, кольцо 104, белая кнопка 54, кобальтовая подложка. При проверке исправлена конкуренция CSS, из-за которой кнопка терялась на синем фоне. Снимок stay.png показывает исправленный результат. Основные шторки используют общий BottomSheet/кнопки приложения. Состояния ключа без собственной визуальной анимационной системы; задержки 650/1000 мс имитируют ответ устройства.

- mantera.png / lighthouse.png: смена поездки меняет изображение отеля; Mantera — лобби из её галереи.
- stay.png: назначенный номер, категория из брони, срок, действия. Полный нижний состав s2 ещё в работе.
- key-success.png: подтверждение прошло, дверь открыта.
- key-error.png: ошибка соединения и повтор.
- key-expired.png: после срока нет кнопки открытия.
- wifi.png: имя сети, пароль и действия в общем стиле.

## Сквозные действия

1. Выбор Mantera → событие заселения → карточка проживания. До события ключ отсутствовал.
2. Открытие → подтверждение → проверка → соединение → успех. Закрытие и повторный вход возвращают стартовый экран ключа.
3. Следующая попытка с ошибкой → сообщение → повтор → успех.
4. Перезагрузка сохраняет проживание. Другая бронь «Маяк» остаётся до заезда и не получает ключ.
5. Истечение срока → «Ключ недоступен» без открытия двери.
6. Детали брони: статус проживания и комната, редактирование/отмена скрыты; возврат ведёт в поездки.
7. Wi-Fi открывается и закрывается. Буфер обмена пользователя при QA не перезаписывался; фактическое подключение сети не реализовано.
8. После QA выбранная бронь возвращена к состоянию до заезда через предусмотренный инструмент; остальные брони и оплаты не менялись.

Автоматические проверки: 132 теста. Новые проверки охватывают галерею, подтверждение заселения, сохранение, владельца, долг при заселении, повтор события, отказ замка, точные границы времени и невалидные часы, запрет изменений после заселения и часы заказов завтрака. Сборка и runtime проходят. Валидаторы подтвердили неизменность 303 исходников и DOCX, согласованность токенов, ассетов и ссылок. Pixel и реальный замок не проверялись.

# Финальная проверка мобильного прототипа · M5/M6

28.10.2026. Проверка в in-app браузере, iPhone и Pixel 10. Это проверка демонстрационного прототипа, не реальных устройств/платежей/замков. Десктоп не входил в объём.

## Что пройдено

- Пять состояний поездки: без брони, до заселения, проживание, день выезда, завершение. После отзыва — компактная оценка; выезд оформляется действием отеля в инструментах. Ключ отсутствует до заселения и после выезда.
- Ранний заезд и поздний выезд: добавление закрывает окно, стоимость попадает в бронь, лейбл «Добавлено» с зелёной галочкой; детали открываются сразу, отмена закрывает окно. Уточнение оплаты находится рядом с ценой.
- Ключ: ожидание → ошибка → повтор/помощь. Ошибка больше не исчезает без доступного действия. Звонок доступен только при наличии известного номера; звонок не выполнялся.
- Поиск: Москва → даты → гости; выдача с длинными названиями/скидками; выбор номера с фотографиями и тарифами; данные гостя; СБП; детализация итоговой суммы.
- Новая бронь Измайлово: 9 100 ₽ − 910 ₽ скидки − 4 860 баллов = 3 330 ₽. Отказ не списал баллы и не создал бронь; повтор создал одну бронь, фото/название/платёж перенеслись в поездку и детали.
- Дополнительный повтор отказа без баллов: один alert, прокрутка до условий отмены, переключение Pixel → iPhone, возврат к гостю. Ошибка очищается при смене шага.
- Production preview :4174: чистая регистрация с тестовым телефоном, маска +7, шесть полей SMS, код 123456 автоматически переводит к имени; продолжение с открытой клавиатурой с первого нажатия. Новый пользователь видит пустые поездки. После полной перезагрузки сессия сохранена. После запуска production новых ошибок консоли нет; исторические сообщения HMR относятся к исправленным промежуточным изменениям dev-сборки.

## Исправления прохода

1. Единая успешная маркировка добавленных услуг времени, включая общий каталог; в UI kit добавлен образец «Добавлено».
2. Постоянное окно ошибки цифрового ключа с понятными дальнейшими действиями.
3. Убран повтор ошибки оплаты в содержимом экрана. Ошибка размещена в нижнем блоке, условия не перекрываются.
4. Контейнер flow-stack больше не прокручивается при фокусе кнопки: overflow:clip в слое приложения. Прокруткой владеет MobileScroll. Под системной строкой есть фон и для booking-scroll; защищённый runtime не изменён.
5. Тайминг оплаты использует общий interactionMotion.paymentWaitMs. Исправлено название подушки с гречихой.

## Автоматические проверки

- 328 тестов пройдено, 0 ошибок/пропусков: tests/*.test.mjs + app/tests/auth.test.mjs.
- TypeScript и production build прошли.
- Runtime integrity: все 28 защищённых файлов совпадают с контрольными суммами.
- Vite предупреждает о крупных чанках: основной JS ≈1,48 МБ (gzip ≈348 КБ), отдельно загружаемые документы ≈1,14 МБ. Оптимизация загрузки и замеры на реальных мобильных устройствах остаются техническим этапом перед выпуском; предупреждение не подавлялось.

## Границы проверки

Матрица содержит 99 функциональных описаний и 23 пути; она не означает 99 новых попиксельных сравнений в этом проходе. Свежая визуальная проверка охватывает перечисленные экраны, остальные опираются на предыдущие отчёты и доменные тесты. Reduced motion сверено по существующим веткам/токенам кода; системное включение на физическом устройстве в этом проходе не проверялось. Загрузка фото использует общий ранее проверенный обработчик; системный файловый диалог заново не проходился. Оплаты, SMS, ответы, push, звонки и доступ к двери остаются демонстрационными.

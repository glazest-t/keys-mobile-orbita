# Проверка сценария отельера · 28.10.2026

Источник: функциональные A05–A07/J11 и макеты z1/z2/z3/z5/z6 «Все экраны». Внешний кабинет — самостоятельная демонстрация, без подключения TravelLine.

Проверено:

- Приглашение без авторизации → телефон → шесть цифр SMS → имя → рабочий email. Доступ в приложение по-прежнему требует входа; само приглашение не выдаёт роль.
- Запрос → отдельная вкладка → отказ, автоматическое обновление исходной вкладки → другая почта → повтор. Старая ссылка показывает недоступный запрос.
- Подтверждение во второй вкладке → зелёное состояние с галочкой в приложении → профиль сохраняет статус.
- Встроенный браузер не представил новую вкладку по target=_blank. Проверен запасной переход «Кабинет не открылся? Открыть здесь», подтверждение и возврат в приложение. Для проверки межвкладочного обмена вкладка открыта инструментом браузера по видимому URL ссылки.
- Подтверждённый пользователь: поиск Сочи → Mantera → выбор номера. Friendly Rate 18 460 ₽ показан рядом с обычными тарифами; принудительной замены выбранного тарифа нет.
- Внешний вид приглашения, ожидания и успешного результата на iPhone; успешный результат на Pixel. Снимки: approved.png, approved-pixel.png.
- 307 тестов пройдены, включая 4 новых проверки: вход, валидация/актуальность запросов, изоляция владельцев и финансовых данных при синхронизации, доступность тарифов по статусам.
- Production build и проверка 28 защищённых runtime-файлов пройдены.

Проверка выполнена на localhost:5173 с тестовыми профилями, отдельно от пользовательского origin 127.0.0.1:5173. Номер телефона, SMS и рабочая почта в тесте вымышленные; реальные сообщения не отправлялись.

Ограничения: никакой реальной проверки сотрудника, аккаунта TravelLine или домена почты нет. Причина демонстрационного отказа фиксирована: «Аккаунт не связан с отелем». Приглашение коллеги и полная программа лояльности в этот проход не входят.

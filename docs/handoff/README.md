## Приоритет источников

Последние прямые решения пользователя → этот актуальный контракт → текущие компоненты приложения и каталог экранов → брендбук 2.0. Функциональный DOCX задаёт базовые сценарии; более поздние изменения пользователя заменяют его старые ветки. Исторические записи `DECISIONS.md`, `ITERATIONS.md`, `iteration-1` и старые отчёты не следует объединять как одновременно действующие требования.

Старые HTML-референсы, альтернативная айдентика и промежуточные дизайн-варианты исключены из текущего репозитория и публикации. Локальные архивные копии сохранены. Актуальные иллюстрации находятся в `app/public/brand/`, токены и графический словарь — в `design/`.

## Запуск и проверки

Из корня проекта, Node с поддержкой `--experimental-strip-types`:

```sh
npm --prefix app run dev -- --host 127.0.0.1
npm --prefix app run check:runtime
npm --prefix app run build
node --experimental-strip-types --test tests/*.test.mjs app/tests/auth.test.mjs
python3 scripts/validate_brand.py
python3 scripts/validate_product_spec.py
```

Прототип: http://127.0.0.1:5173/ · живой каталог: `#kit`.
Брендбук: запустить `python3 -m http.server 4173 --bind 127.0.0.1` из корня, открыть `/docs/brand/index.html`.

СМС `123456`, PIN демосценариев `1234`. Шесть входов и пять состояний поездки переключаются в инструментах вне телефона. «Вернуться к своим данным» выходит из демонстрационного набора. «Сбросить» удаляет локальную демонстрацию; для обычной проверки он не нужен.

## Границы реализации

- React + TypeScript + Vite; данные на устройстве. `state.ts` — профиль/авторизация, `booking/model.ts` — Commerce, `prototype/domain/` — общий расчёт денег и платежей. Это не схема будущего сервера.
- Деньги в минимальных единицах валюты, баллы целые. Снимок расчёта хранится в брони. Компоненты не должны самостоятельно менять баланс.
- Защищённые 28 файлов мобильного runtime не редактировать. Оболочка, клавиатура, BottomSheet, Carousel и MobileScroll уже обеспечивают поведение устройства; правила в `app/AGENTS.md`.
- Новые UI-состояния добавлять в действующие компоненты. Не копировать экран в независимый «UI kit» с другими стилями.
- Сборка не доказывает визуальное соответствие. Перед сдачей сценария нужны браузерная проверка переходов, клавиатуры, прокрутки и нижнего действия на iPhone и Pixel.
- Визуальная приёмка пользователя ещё не завершена. Прототип не следует объявлять готовым к production или нативному выпуску.

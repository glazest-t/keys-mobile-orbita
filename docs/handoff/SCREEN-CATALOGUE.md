# Все экраны текущего мобильного приложения

[Открыть каталог](https://glazest-t.github.io/keys-mobile-orbita/screens.html).

Каталог собирается из `app/src/catalogue/scenes.json`. Каждая карточка открывает текущий React-прототип с определённым состоянием, а не копию исходного HTML. Фотографии, стили, компоненты, прокрутка и взаимодействия общие с приложением. Разделы и поиск помогают найти нужный экран; «Сначала» сбрасывает только конкретное превью.

## Отдельные данные

`app/src/catalogue/fixture.ts` создаёт вымышленный профиль, кошельки, брони, избранное и нужную стадию поездки через существующие функции домена. Превью не читает и не сохраняет состояние основного прототипа. Новый просмотр начинает независимый сценарий. Демосценарии не являются способом авторизации реального пользователя.

Маршрут `?catalogue=<id>#<route>` открывает тот же экран отдельно. `replay.ts` раскрывает окна через текущие кнопки. Если кнопка исчезла или переименована, каталог показывает ошибку подготовки вместо молчаливой подмены другим экраном.

## Состав и границы

Каталог включает маршруты мобильного приложения и отдельные значимые состояния: три шага онбординга, обычного гостя/отельера, этапы бронирования, пять стадий поездки, основные шторки, программы и настройки. Повторяемые строки каталога отелей и все возможные комбинации пользовательских данных не считаются отдельными экранами. Нативные диалоги ОС и внешние интеграции здесь не подменяются нарисованными обещаниями.

Удалённые сценарии (депозит, онлайн-регистрация, обязательная подготовка к выезду, прежний многошаговый подбор) не включаются. Архивные ID исходных макетов остаются только исторической картой происхождения в Git; визуальным источником являются текущие компоненты.

## Обновление

Изменение компонента автоматически обновляет его превью при следующей сборке. При добавлении нового экрана нужно добавить сцену в JSON, необходимые данные в fixture и проверить открытие. Брендбук использует те же сцены. Публикация `npm --prefix app run build:pages`, проверка `python3 scripts/validate_pages.py`; браузерная проверка всех рецептов — `screens.html?verify=1`.

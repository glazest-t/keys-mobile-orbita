## Статусы

| Смысл | Подпись | Вид |
|---|---|---|
| Ранний заезд / поздний выезд добавлен | Добавлено | success + check; даже если бухгалтерский заказ уже исполнен/оплачен |
| Платная услуга ожидает оплаты | К оплате | warning + pending |
| Платная услуга оплачена | Оплачено | success + check |
| Бесплатная услуга принята | Заказано | success + check |
| Нужен ответ по произвольному запросу | Ждёт ответа | warning + pending |
| Отклонено | Отклонено | error + close |
| Отменено | Отменено | neutral + close |
| Уровень программы | Ваш уровень | success + check |

В деталях брони список услуг не дублирует все эти статусы: пользователь отдельно попросила убрать там «Выполнено/Оплачено» и даты. Отмена услуги закрывает окно и даёт Toast. Статус не должен заменять основное действие оплаты.

## Навигация, прокрутка и safe area

Шапки страниц прокручиваются с содержимым. Исключение — шапка диалога с кнопкой назад, закреплённая по отдельному решению пользователя. Нижнее меню — четыре раздела с двигающейся подложкой, без точки. Колокольчик — индикатор новых событий без числового счётчика.

Нижние действия бронирования/услуг/программы отеля размещаются вне MobileScroll, контент получает отступ под реальную высоту панели и safe area. Шторки — в портале; при показе скрывается клавиатура. Статусная строка и навигационная зона устройства принадлежат runtime. На подтверждении бронирования применяется `page-scroll`, чтобы success не попадал под системную строку.

Источник общих значений: `interactions.tsx` и `interactions.css`; онбординг отдельно `onboarding/motion.ts` (D-011). [Таблица брендбука](../brand/motion.json) различает реализованное движение и нативные справочные эффекты.

| Заставка | 2400 мс, один ключ/орбита перед каждым входом; биометрия объединена с ней |
| Биометрия / успех | authCheckMs 900, authSuccessMs 420; результат на той же заставке; ошибка ведёт к PIN |
| Открытие двери | keyOpeningMs 1100; keySuccessHoldMs 3000; повтор блокируется до завершения |

| Баллы | 1,4 с, орбита и счётчик; анимация сама не начисляет деньги/баллы |

Пружины защищённых BottomSheet/клавиатуры — реализация runtime; не выдавать целевые миллисекунды исходного каталога за точную физику браузерной шторки. Нативная хаптика в браузере не реализована.

## 03.11.2026 · Доплата частично оплаченной брони

`BookingPaymentStatus.tsx` показывает статус и действие «Оплатить полностью» в поездке, подтверждении и деталях. `bookingBalance.ts` определяет частичную оплату по факту внесённых денег/баллов и ненулевому остатку, принимает платеж ровно на остаток основной операции. Отдельные послеброневые услуги не смешиваются с этой суммой.

Прототип открывает демонстрационный экран эквайринга с тестовой картой без ввода реальных реквизитов. Отказ/закрытие сохраняют остаток; успех обновляет операцию, увеличивает ревизию и записывает `balancePayments`. Повторный event ID не создаёт нового списания. Устаревшая сумма/ревизия, чужая или отменённая бронь отклоняются. После доплаты изменение дат рассчитывается как полностью оплаченная бронь.

Для production необходимо создавать платёжную сессию на сервере и обновлять оплату только после проверенного уведомления эквайера. Клиентский успешный переход сам по себе не подтверждает списание. В текущем прототипе всё это симулируется.

Примеры каталога: `booking-partial-payment`, `trip-partial-payment`. Проверки: `tests/booking-balance.test.mjs`, `.desktop-work/qa/booking-balance.mjs` (локальный desktop QA).

03.11.2026 · `BookingReward.tsx` — общий блок ожидаемых баллов за бронирование для десктопной корзины и мобильного оформления/подтверждения. Отменённые и завершённые брони не показывают ожидание начисления.

## Десктоп: попап услуги · 04.11.2026

Вход из поездки, списка услуг или оформления брони открывает детали в диалоге над текущей страницей. Завтрак сразу показывает настройки заказа, без промежуточной страницы. Закрытие возвращает к исходному контексту; переход к оплате заменяет диалог, не наслаивает его.

Структура: название услуги в шапке → изображение/фирменная иллюстрация → описание и принцип расчёта → настройки → итог и действие. Общий `ServiceDetailIntro` находится в `app/src/booking/ServiceDetailIntro.tsx`; оформление — `desktop/src/service-dialogs.css`. Изображения берутся из существующих локальных материалов проекта. Диалог шириной до 720 px ограничен viewport; длинный контент прокручивается, итог остаётся видимым. Группы действий слева, primary/secondary.

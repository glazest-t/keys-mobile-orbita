## 1. Вход и доступ

Мобильное приложение доступно **только после авторизации**. До неё доступны вход, онбординг, приглашение и условия. Гостевой поиск без авторизации не возвращать.

| Вход | Последовательность |
|---|---|
| Новый обычный пользователь | Общая заставка ключа → онбординг → телефон → СМС → имя → приложение |
| Установка по приглашению отельера | Заставка → «Свои отели. Особые условия» → принять → регистрация и подтверждение статуса → онбординг → приложение |
| Приглашение пропущено | Регистрация → онбординг → приложение с баннером подтверждения статуса; Friendly Rate ещё недоступен |
| Зарегистрированный отельер | Заставка → телефон → СМС → приложение с подтверждённым статусом |
| Зарегистрированный обычный гость | Заставка → телефон → СМС → приложение без статуса и без предложения подтвердить его |
| PIN | Заставка → четыре цифры → автоматическая проверка → приложение |
| Биометрия | Одна общая заставка с проверкой → успех → приложение; при ошибке/недоступности — PIN |

На телефоне нет крестика закрытия. СМС — шесть ячеек, правильный код показывает общий success и переходит автоматически. PIN — четыре ячейки; есть ошибочный ввод и восстановление. Телефон маскируется, редактирование профиля допускает международные номера. Ссылка «условия» открывает страницу условий.

Подтверждение статуса в демонстрации имитирует TravelLine. «Подтвердить позже» снимает текущую заявку (`none`), сохраняя признак приглашения и баннер. Не показывать статус `approved` по одному переходу на экран. Обычному гостю без признака приглашения вход подтверждения в профиле не показывается.

## 2. Поиск и подбор

- «Найти»: единая формулировка «Лучшие цены напрямую от отелей». История появляется только после поиска и расположена над свайп-подбором. Текстовый подбор — внизу. «Горячие скидки» — выбранный вариант 2, весь баннер кликабелен, без отдельной круглой кнопки.
- «Куда поедем»: полноэкранная шторка, поле на всю ширину, крестик внутри. Только популярные направления; нет недавних и геолокационного блока. Выбор города или подтверждение найденного города → даты → гости. Независимое открытие дат показывает календарь; гостей — состав гостей.
- Редактирование параметров из выдачи и выбора номера — общий k3. Особенности поездки доступны при поиске, не при изменении брони.
- Выдача: компактная строка города/дат/гостей с карандашом, фильтры и сортировка в одном ряду. Сортировка — только иконка. Шапка не залипает при скролле (последнее решение заменяет D-017). Карта раскрывается как c2.
- Фильтры: полный состав из DOCX поиска; черновик применяется по кнопке. Сортировка применяется сразу. Сети по алфавиту. «🔥 Только в Ключах» с отдельной i-кнопкой объяснения в BottomSheet. Цена переключается за ночь/срок в заголовке группы.
- В карточках фото листаются, избранное розовое. Обычный список и карта используют один набор фильтров и цен.
- Текстовый подбор: описание → «Подобрать отели» → сразу выдача с тегами пожеланий, фильтрами, картой и карточками. «Почему подходит вам» закрыто по умолчанию, без счётчика совпадений и промежуточного опроса.
- Свайп: первый вход открывает «Ваш стиль путешествий»; настройки позволяют вернуться и сохранить. Пузырьки появляются, выбор даёт водные кольца, переход собирает орбиту. Лайк сразу сохраняет в «Подборка по свайпу» без выбора коллекции/тоста; кнопка всегда синяя с белым контурным сердцем. Нажатие на края медиа листает галерею, свайп вверх меняет отель. Шапка и системная строка тёмные.
- Избранное: коллекции, карта коллекции, отсутствие мест явным лейблом. В слежении за ценой показываются фото, отель, номер, цена/изменение и тумблер; отдельные демопримеры ±5 500 ₽.

## 3. Отель и бронирование

h1/h2/h9/n1/d5/x1/w1 остаются визуальными ориентирами: фото, «Под ваши предпочтения» с объяснением и переходом к настройкам, «Цена для вас», расположение, маршрут, отзывы и наблюдение цены. Цвет иконок ссылки наследует её цвет. В детализации цены нет повторной подсказки о применении баллов; доступные баллы обычным начертанием.

Выбор номера: без фильтров, дат/гостей под заголовком и числа ночей в заголовке. Справа редактирование параметров, фотографии листаются. Оснащение и тариф — общие шторки в стиле расчёта цены.

Данные бронирования (h5): сводка отеля → времена заезда/выезда → гость → дополнительные гости/услуги → пожелания. Основной контакт заполняется из профиля; поля редактируемы, можно вписать другого человека. Нет «Для себя/другого» и выбора путешественников в основном блоке. Выбор сохранённого путешественника доступен при добавлении дополнительного гостя, автоподстановка сохраняется. В пожеланиях нет разделителей строк и лишнего заголовка над свободным вводом.

Время заезда/выезда до оплаты выбирается из настроек отеля; доплата включается в общий расчёт. Стандартное время убирает услугу. Услуга не дублируется в общем списке. При отсутствии настроек доступно стандартное время.

Подтверждение/оплата: программа отеля перед способами оплаты; СБП первым и по умолчанию; способы карточками в горизонтальной карусели, дополнительные в «Другое». При выключенном списании строки балансов скрыты, нулевые кошельки не показываются. Отмена — после налогов в конце. Итого внизу раскрывает состав цены. Успех показывает услуги из брони; полной оплате соответствует зелёная отметка справа.

### Цена и кошельки

- На оплате бронирования (включая добавленные в неё услуги): максимум доступных баллов в пределах 100% заказа либо без списания. Сначала кошелёк отеля, затем «Ключей»; это рабочее распределение в общем расчёте. Кошельки раздельны.
- **Отдельная оплата услуги после бронирования:** переключателя баллов «Ключей» нет; текущий UI передаёт `usePoints=false`. Не переносить туда автоматически правила оплаты брони. Старый депозитный код сохранён для совместимости, входы и способы оплаты депозитом удалены.
- Friendly Rate: только `approved`, −35% от соответствующего обычного тарифа во всех 53 демоотелях. Обычные тарифы доступны. FR исключает скидку/баллы/начисление программы отеля, но разрешает баллы «Ключей» при бронировании.
- Название всегда **Friendly Rate**. Лейбл в расчёте стоит в строке скидки, не под заголовком; в сводке брони не дублирует название выбранного тарифа.
- Отказ оплаты не меняет баланс и не создаёт бронь; повтор защищён от дублей. Цена/баланс проверяются перед подтверждением.
- Отмена проживания: бесплатно за 3 дня до заезда включительно, позже одна ночь. Возврат денег и баллов раздельный. Распределение удержаний — рабочая модель P-013, не новая договорная политика.

## 4. Поездка, услуги и выезд

| Состояние | Что видно и доступно |
|---|---|
| Нет активной брони | Пустой блок с выбранной иллюстрацией, поиск, первый вариант «Двойной выгоды» → Выгоды, история поездок. Подбора по желаниям здесь нет |
| До заезда | Фото именно забронированного отеля; маршрут, инструкция, услуги, детали и поделиться. Цифрового ключа нет |
| Проживание | Номер, ключ, услуги, Wi-Fi, проблемы и чат. Ключ: один клик → 1,1 с ожидания → успех на 3 с → готов |
| День выезда | Проживание и компактное информационное напоминание. Нет обязательного гостевого флоу «Подготовиться к выезду» |
| После выезда | Ключ закрыт; s4, баллы, оценка внутри главного блока. После отзыва — компактная строка. Документы и связь с отелем, повторное бронирование |

Заселение и выезд подтверждает отель; в прототипе это демоуправление. Статус оплаты, стадия проживания и статус брони независимы. «Детали» и «Поделиться» — одинаковые компактные кнопки в одной строке до/после заезда. QR и ссылка общие; чтение не разрешает изменения, управление даёт права владельца. Между устройствами реальная передача не работает без сервера.

### Услуги после бронирования

- Ранний заезд и поздний выезд видны только при доступности. Выбор времени показывает цену; добавление сразу сохраняет в бронь, закрывает шторку и показывает хинт. Оплаты в приложении/ожидания отеля нет. Ранний — «Оплата при заселении», поздний — «Оплата при выезде» в строке цены.
- У добавленного времени статус **«Добавлено»**, зелёный с галочкой; не «Выполнено» и не «Оплачено». Подробнее сразу открывает заказ под названием услуги. Отмена доступна по жизненному циклу; после подтверждения закрывается и показывает хинт, без повторной детализации.
- Услуги с известной ценой сразу идут на оплату; бесплатные не требуют платежа. Ожидание оплаты и оплаченный заказ визуально различаются. Наличие заказа не мешает «Добавить ещё».
- Завтрак можно заказать на дату или все дни. В форме нет комментария/блока условий отмены; в оплате нет повторных «Дат завтраков». Компактная сводка заказа соединена с нижним действием. После успеха «Готово» возвращает в поездки.
- sv1: без поиска, названия отеля/дат и поясняющих абзацев. Категории — чипами. В деталях брони список услуг без дат и повторных «Выполнено/Оплачено».
- Депозит удалён из интерфейса. Счёт доступен в деталях проживания по условиям сценария, а не отдельными блоками на поездке/услугах.
- Строки бесплатной отмены услуг скрыты. Расчёт возврата сохранён: завтрак до 20:00 накануне, ранний заезд за сутки, позже без возврата — утверждённые демоправила. Другие условия услуг — настройки отеля; не выдумывать их как общую политику.
- Обращение о проблеме можно отменить; история сохраняется. Отзыв после выезда, без нового денежного обещания за отзыв и без чаевых.

## 5. Чаты, уведомления и профиль

Чаты без поиска, «Написать в другой отель» и отдельного блока поддержки. Выбранный вариант 2: компактный список с фото, выделение ближайшей/текущей поездки, непрочитанное и спокойный брендовый AI-вход в текстовый подбор. В диалоге закреплены заголовок и назад; подпись AI рядом с названием, без «ответит за 5 минут», дат и брони. Справа звонок при наличии телефона и уведомления отеля. Пресет сразу отправляется. Ответы локальные сценарные, не реальный ИИ.

Общий колокольчик показывает точку, не число. Уведомления, открытые из чата, отфильтрованы по отелю, без дублирования его названия в шапке. Типы исходной таблицы представлены демонстрационными событиями; реального push нет.

Профиль — выбранный вариант 1 с группировкой по смыслу, фото и баллами. ## 6. Выгоды и уровни

Баллы «Ключей» и гостиничные кошельки раздельны. Приветственные 1000 баллов есть в истории один раз. Демоистория начислений/списаний объясняет исходный баланс, не начисляется при каждом открытии. За приглашённого друга обещаны 1000; событие начисления требует решения.

В карточках программ: скидка мятная, баллы нейтральные без орбитального знака «Ключей» и без слова «отеля» внутри метки. Поддерживаются скидка, баллы, сочетание. «Орбита в лесу» — пример только баллов. Отключения карты в UI нет.

Уровни: общий `HotelLevels`, произвольные названия/условия/высота, таймлайн из истории поездок. **Текущий вариант 3:** белая карточка, кобальтовый акцент слева и название, мягкая тень, зелёный статус «Ваш уровень». Не возвращать сплошную синюю/мятную карточку вариантов 1/2. Количество привилегий скрыто в списке; сами привилегии в BottomSheet. «Забронировать» закреплено внизу.

Расчёт: уровень определяется годовой квалификационной суммой по отелю, а не балансом баллов. Новая бронь сохраняет снимок уровня, скидки и начисления; существующая не пересчитывается. После подтверждённого выезда начисление однократное. Friendly Rate исключён. Конкретные пороги, ежегодный пересчёт, проценты и привилегии — демонстрационная конфигурация, см. OPEN-QUESTIONS.

Код: `rewards/loyalty.ts`, `points.ts`, `Rewards.tsx`, `HotelLevels.tsx`, `HotelProgramDetails.tsx`, `hotelier/FriendlyRateBadge.tsx`. Тесты: `rewards.test.mjs`, `hotel-levels.test.mjs`, `hotelier.test.mjs`.

## Сохранение и ошибки

Данные разделены по владельцу и bookingId/отелю. Переход к другой поездке не подменяет черновик поиска. Возврат из вложенного экрана ведёт к инициатору. Платёж/возврат/выезд/награда защищены от повторного применения. Изменившиеся цена, доступность или кошелёк требуют пересчёта, а не тихого подтверждения старой суммы.

`localStorage` — только демонстрационное хранилище. Авторизация, роли и права доступа на клиенте не заменяют серверные проверки. Не переносить локальные PIN, токены приглашения, QR-доступ и платёжные методы в production без отдельной серверной архитектуры.

## Уточнения мобильной приёмки · 30.10.2026

Последние решения: блок свободного описания удалён только с «Найти» (вход из AI-ассистента в чатах остаётся). При первом открытии «Найти» новым зарегистрированным профилем — однократная шторка «Ваш стиль путешествий», фиксация показа сразу, сохранение выбора через общий механизм предпочтений. Повторный вход/перезапуск не повторяет шаг. Прежние профили не мигрируются в «новые».

Все цены округляются до целого рубля в представлении; финансовое ядро сохраняет копейки. Прочие способы оплаты — BottomSheet с применением по выбору. «Номера рядом» не предлагается. Подтверждение оплаты/брони показывает BookingRecord с теми же данными, услугами, документами и действиями, что и повторное открытие деталей; подсказки о ключе снизу нет.

До заезда доступны места рядом с отелем и заметный статус оплаты. Завтрак во время проживания показывает время, место и фактическое состояние: включён, оплачен, добавлен либо ожидает оплаты. Баннер приглашения друзей находится перед «Вашими возможностями».

## 30.10.2026 · Тип тарифа и оформление оплаты (последнее уточнение)

Оформление определяется условиями доступа, а не наличием скидки:

- Общедоступный тариф без скидки — белая карточка.
- Общедоступный тариф со скидкой программы отеля — также белая карточка.
- Закрытый тариф для определённого уровня отеля — тёмная карточка с плашкой уровня гостя.
- Friendly Rate — тёмно-зелёная карточка, доступна только подтверждённому отельеру.

Единая проверка `rateAccess.ts` применяется в списке номеров, выборе тарифа, создании и расчёте черновика. Для демонстрации добавлен `sea-standard-connoisseur`: закрытый тариф с завтраком для «Ценителя» и выше. Доступ старшим уровням — рабочее правило демонстрации; цена взята из существующего тарифа с завтраком, дополнительные скидки не придуманы. Размер обычной скидки по уровню берётся из настроек программы (в текущем примере 5%, не фиксированные 10% из пояснения пользователя).

У выбора предоплаты нет заголовка «Когда оплатить»; он сгруппирован со способом оплаты картой. В расчёте — «Проживание за 2 ноч.» и «Скидка на проживание −5%», без точки-разделителя. В подтверждении и повторном просмотре статусы оплаты справа; действие изменения брони с иконкой карандаша.

До заезда общая стоимость, ночи и гости собраны в первую строку компактного блока; во второй — остаток «Оплата в отеле» либо зелёный статус «Оплачено». Общая сумма и остаток не смешиваются. Проверка: `docs/iteration-9/qa-rate-rules-2026-10-30/REPORT.md`.

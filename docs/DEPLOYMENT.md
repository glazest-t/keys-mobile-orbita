# Публикация проекта · GitHub Pages

Репозиторий: https://github.com/glazest-t/keys-mobile-orbita

Сайт: https://glazest-t.github.io/keys-mobile-orbita/

## Разделы сайта

- `/` — стартовая страница проекта.
- `/prototype/` — мобильное приложение со всеми существующими инструментами демонстрации. СМС: `123456`, PIN: `1234`.
- `/screens.html` — все 117 исходных мобильных макетов и каталог 99 функциональных описаний. Окна, требующие бронь, открываются через соответствующий сценарий поездки.
- `/documentation.html` — навигация по документации. Markdown преобразуется в HTML, исходный Markdown остаётся для скачивания.
- `/docs/brand/index.html` — брендбук; живой UI kit находится в `/prototype/#kit`.

Макеты — неизменённые исходные визуальные эталоны. Актуальное поведение — в приложении и `docs/handoff/`. Страница всех экранов не заявляет, что старые макеты обновлены до последних решений пользователя.

## Обновление

Push в `main` запускает `.github/workflows/pages.yml`: установка зависимостей → контроль runtime → тесты → проверки спецификации/бренда → сборка и проверка локальных ресурсов → публикация Pages. Вручную можно запустить workflow «Publish project» во вкладке Actions.

```sh
npm --prefix app ci
npm --prefix app run build:pages
python3 scripts/validate_pages.py
```

Для локальной проверки именно публикации (не Vite):

```sh
mkdir -p .pages-preview
ln -s ../_site .pages-preview/keys-mobile-orbita
python3 -m http.server 4180 --directory .pages-preview
```

Адрес: `http://127.0.0.1:4180/keys-mobile-orbita/`. Если ссылка уже существует, повторно создавать её не нужно.

## Что публикуется

В `main` — исходный код приложения, спецификации, документация, дизайн/варианты, исходный экспорт, ассеты и QA. Зависимости `node_modules`, временная папка `tmp`, локальные `.env`, сборки и кэши исключены. Личные данные браузера/localStorage в репозиторий не экспортируются.

В Pages — статическая сборка, документы, дизайн и источники. `app/scripts/build-pages.mjs` адаптирует пути ресурсов только в выходной папке `_site`; защищённый runtime и исходный экспорт не изменяются. Не редактировать `_site` вручную: новая сборка его заменит.

Данные и токены демонстрации остаются локальными для данного origin. Они не синхронизируются между локальным прототипом, GitHub Pages и другими устройствами. QR/приглашения и подтверждение TravelLine демонстрируют интерфейс, но не создают серверную интеграцию. Все платёжные действия тестовые; настоящие данные карты вводить не требуется.

Для production сохраняются вопросы из `docs/handoff/OPEN-QUESTIONS.md`, включая правила программ, интеграции и права на внешние материалы.

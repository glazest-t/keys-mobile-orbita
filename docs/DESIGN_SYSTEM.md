# Бренд и UI kit Ключей

Выбранное направление: **Onest + Unbounded, кобальтовый #2F5BFF**. Главный визуальный источник — **«Ключи — Все экраны»**: пользователь просит максимально сохранить его дизайн. UI Kit и brand-kit дополняют макеты. Итерация 2 подготовлена: [визуальный брендбук](brand/index.html), [описание решений и ассетов](brand/README.md), [токены](../design/tokens.json). Живая библиотека компонентов работает в #kit; актуальные паспорта — [комплект для разработки](handoff/COMPONENTS.md).

## Ядро бренда

Название продукта — «Ключи», концепция — «Орбита». Кольцо объединяет отели, точка обозначает гостя. Характер: спокойный, точный, тёплый; технологичность выражается в понятном действии. Текущая фраза — «Ключи от всех отелей». Прежняя «Вы — в центре» оставлена только в неизменяемом архиве.

Интерфейс светлый, с перламутровым фоном и кобальтовым акцентом. Стекло и объём подчинены читаемости. Голос — коротко, на «вы», без рекламного давления. Премиальность не должна усложнять поиск, оплату или работу с ключом.

## Базовые значения выбранной системы

Для разработки используется `design/tokens.json`. Он объединяет исходные brand-kit токены с проверенными значениями из «Все экраны». Точные различия и их происхождение перечислены в [брендбуке](brand/README.md).

| Категория | Значения |
|---|---|
| Бренд | cobalt #2F5BFF; tint #EEF0FF; pressed #1E44DB |
| Текст | ink #101320; slate #5A6072; muted #8A90A2 |
| Поверхности | pearl #F4F5FB; white #FFFFFF; line #E4E7EF |
| Состояния | success #16865A / #BFF0DE; warning #B7791F / #FFF3D6; error #E5484D / #FDE8E8 |
| Шрифты | Unbounded 500 для крупных заголовков и чисел; Onest 400/500 для интерфейса и текста |
| Сетка | Базовый шаг 4; поля контента 16, шапки 20; между блоками 12; между секциями 24 |
| Радиусы | 8, 12, 14, 16, 22, 28, 32; pill 999 |
| Кнопки | Основная 52 с радиусом 16; ключ 54; вторичная 44; минимальная интерактивная область 44 |
| Иконки | Сетка 24, stroke 1.5, круглые соединения, currentColor |

Текущие HEX и размеры не заменяют проверку контраста и читаемости каждой комбинации. Например, muted нельзя автоматически применять к мелкому значимому тексту. Все финальные компоненты проверяем в контексте.

## Единые токены

Предлагаемая организация: исходные значения → семантические роли → токены компонентов. Например, кобальт становится `action.primary.background`, а не отдельным HEX в каждом экране. Система покрывает цвет, типографику, сетку, размеры, радиусы, тени, слои, движение и адаптивность.

В итерации 2 добавлены роли Friendly Rate, выгод, текста ошибок и предупреждений; согласованы кнопки, шапка и стекло меню. Детальные состояния шторок, форм и переходов дополняются при сборке живого UI kit, сохраняя конкретный макет. Значения JSON и CSS проверяются на соответствие.

## Паспорт компонента

Для каждого компонента нужны назначение, варианты, входные данные, события, состояния, токены, поведение при длинном контенте, правила фокуса/клавиатуры, адаптивность и примеры на реальных сценариях. UI kit включает живые примеры, а не только изображения.

Общие требования: содержательные подписи; ошибка объясняет дальнейшее действие; состояние не кодируется только цветом; шторка возвращает фокус; клавиатура не скрывает поле и подтверждение; уменьшенное движение отключает пространственные эффекты; touch и desktop поддерживаются подходящими композициями.

## Связь с исходниками и разработкой

Для каждого реализованного маршрута ведём связь «ID исходного экрана → маршрут → компоненты → проверка». Новые экраны используют библиотеку, библиотека пополняется по реальной потребности. Повторно размножать inline-стили или делать отдельный UI kit, не используемый приложением, не следует.

Брендбук передаётся как локальная HTML-страница, JSON/CSS и SVG. Базовый живой каталог реализован: app/, маршрут #kit. [Паспорта компонентов](iteration-3/COMPONENTS.md). Предметные компоненты поиска, брони, услуг и уровней реализованы; живые примеры и источники перечислены в [актуальном реестре](handoff/COMPONENTS.md). Figma может стать дополнительной библиотекой по отдельному запросу.

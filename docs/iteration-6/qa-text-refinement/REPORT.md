# P-036 · Районы и резюме текстового подбора

28.10.2026. Вход: Найти → Опишите свой отдых → Подобрать отели.

## Реализовано

- Для конкретного города с несколькими районами — отдельный выбор по nc9: схема, список и число подходящих отелей в каждом районе. Вариант «Неважно, где жить» снимает ограничение.
- Для «Куда угодно» и города без выбора районов — сразу резюме nc10. Район другого города игнорируется; при выборе нового города в форме район очищается.
- Резюме: орбита с актуальным количеством, исходные иллюстрации интересов, город/район, даты, гости, бюджет и пожелания; переход в существующую выдачу.
- Повторный выбор района из выдачи применяется по кнопке. Назад отменяет несохранённый выбор, возвращая прежнюю выдачу. Из резюме можно вернуться к району или изменить пожелания.
- Сохранение этапа, применённого района и условий по владельцу; обычный поиск и отдельный старый опрос не перезаписываются. Детали отеля получают прежний returnTo и фактические совпадения.

## Проверено

297 тестов прошли, включая четыре новых проверки районов, счётчиков, бюджета/дат, чужого города, сохранения и переходов назад. Production build, TypeScript и 28 защищённых файлов runtime прошли. Vite сохраняет прежнее предупреждение о размере чанков.

Браузер iPhone: пожелание «Бассейн и тишина» → три отеля в Сочи; Сириус → один отель; резюме → Mantera → перезагрузка → возврат в ту же выдачу. Выход из редактирования с другим районом без применения сохраняет Сириус. Снятие района возвращает три отеля. Обратный переход резюме → районы работает.

Pixel10: резюме и действия помещаются; бюджет до10000₽ даёт ноль, показано корректное пустое состояние без кнопки просмотра несуществующих результатов. Снятие бюджета восстанавливает результат. На iPhone все нижние действия доступны при прокрутке выше меню. Консоль без ошибок.

Снимки: districts.png, summary.png, results.png, summary-pixel.png, empty-pixel.png. При первом проходе общий класс k-list-row навязывал трёхколоночную сетку и ломал текст. Заменён на k-surface-action с теми же общими реакциями; повторная визуальная проверка подтверждает нормальные строки.

## Визуальная основа и границы

Исходные nc9/nc10 изучены по HTML: шрифты Onest/Unbounded, 24/30 заголовок районов, карта170px, белые строки22px, орбита260px и кольцо16px, заголовок итога26/32. Сохранены исходные ассеты интересов и общие компоненты/тайминги. Резюме дополнено фактическими условиями. Схема районов демонстрационная, без географически точной карты; показываются первые четыре района на схеме и полный список ниже. Рекомендации о тишине/расстояниях районов не выдумывались.

Полная nc11 с темпом/окружением не реализована. Старый пошаговый опрос не расширялся и не возвращён в поездки. Реальный ИИ и карты не подключены. Текстовый парсер сохраняет прежние ограничения. Изменение коммерческих правил не требуется.

Результат прохода: проверено.

# Айдентика и брендбук · мобильная версия 1.3

30.10.2026: актуальные компоненты, исключения из исходных макетов и правила передачи — [handoff](../handoff/README.md). Примеры старых экранов ниже являются эталоном композиции, а не актуальными бизнес-правилами.

Визуальная основа — **«Ключи — Все экраны»**. Пользователь отдельно подтвердила 21.10.2026, что этот дизайн максимально близок желаемому результату. Сохраняем его; допустимы небольшие изменения для согласованной логики и читаемости.

## Просмотр

[Визуальный брендбук](index.html) содержит знак и логотип, палитру, типографику, композицию, фотографию, иконки, голос, движение и ссылки на материалы. Внутри можно переключать девять исходных экранов. Эти макеты имеют исторические подписи и суммы; их оформление является эталоном, бизнес-правила — нет.

Запуск из корня проекта:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:4173/docs/brand/index.html`. Прямое открытие HTML с диска ограничивает загрузку JSON в некоторых браузерах. Брендбук и его шрифты работают локально без подключения к CDN.

Часть фотографий внутри извлечённых эталонов h1/fr3/fr4 загружается с исходного сайта отеля и требует сети. Эти ссылки сохранены, а не заменены случайными изображениями. Основные материалы брендбука, локальные шрифты, логотипы и иконки находятся в проекте.

## Суть бренда

«Ключи» объединяют выбор отеля, бронирование и управление проживанием. Основная аудитория — гость, которому нужен понятный путь от поиска до выезда; подтверждённый отельер пользуется тем же продуктом с дополнительным тарифом. «Орбита» — концепция айдентики: кольцо обозначает отели, точка — гостя и этап его поездки. Основная фраза — «Ключи от всех отелей».

Характер — спокойный, точный и тёплый. Качество выражается в ясных действиях, аккуратных деталях и свободном пространстве. Светлое оформление, выразительный заголовок и один основной акцент помогают выбрать следующий шаг. Визуальные обещания не подменяют реальные условия тарифа, баллов или доступа к ключу.

## Приоритет источников

1. Прямые решения пользователя: дизайн «Все экраны», логика из D-005–D-008.
2. Конкретный макет «Все экраны» для композиции и значений его компонентов.
3. Нормализованные [токены](../../design/tokens.json), дополняющие выбранные экраны.
4. `brand-kit` и UI Kit — для пробелов и общих правил, без автоматической подмены макетов.

Golos Text / «Орбита 2.0» не смешиваются с выбранным направлением. Рамка телефона, время 9:41 и служебные подписи ID относятся к демонстрационному холсту, а не к интерфейсу будущего приложения.

## Разрешённые изменения

- Подставить рассчитанные суммы вместо старых значений; показать отдельные кошельки, максимум списания и нулевую доплату.
- Убрать онлайн-регистрацию, показывать ключ только после фактического заселения.
- Развести доступный, ожидающий и отклонённый статус отельера; не скрывать обычные тарифы у подтверждённого отельера.
- Дать место длинным названиям, ошибкам и загрузке; сохранить форму карточки и иерархию.
- Расширить невидимую область нажатия до 44 px и обеспечить фокус, контраст и спокойное движение.

Смена сетки, основного цвета, шрифтов, формы карточек, фото-стиля или композиции ключевых экранов — отдельное решение, не побочный эффект технической сборки. Новые состояния собираются из существующего языка.

## Нормализация значений

| Деталь | Старый brand-kit | Принято для разработки | Источник |
|---|---|---|---|
| Радиус основной кнопки | 14 px | 16 px | f1/s2; отдельные компактные кнопки сохраняют свой вариант |
| Заголовок 26/32 | −2% | −0,8 px | f1/v1 |
| Стекло меню | rgba(255,255,255,.72) | #FFFFFFC4 | f1/s2/v1 |
| Поля шапки | Общие 16 px | 20 px; контент 16 px | f1 |
| Кнопка ключа | Общие 52 px | 54 px | s2 |
| Friendly Rate | Отсутствует в JSON | Градиент #063F3C → #0B6B63 → #13A08D | fr4 |
| Выгоды | Отсутствуют отдельные роли | Градиенты rewards и loyaltySoft | v1 |

В [tokens.json](../../design/tokens.json) есть примитивы, смысловые роли, параметры компонентов и происхождение изменений. [tokens.css](../../design/tokens.css) генерируется из тех же данных. Сначала сверяем компонент с его конкретным макетом: токен не должен насильно выравнивать осмысленные различия.

Контрастная оговорка: исходный muted #8A90A2 не подходит для мелкого значимого текста на светлом фоне — используется slate #5A6072. Для текста ошибки и предупреждения добавлены более тёмные роли #BE3040 и #855609; исходные цвета остаются для графики. На фотографиях и светлых участках градиента нужна локальная подложка под мелкий текст. Полный аудит каждого будущего компонента проводится в UI kit.

## Ассеты и воспроизводимость

В `design/assets/` подготовлены **140 файлов**: исходные иконки, логотипы, app icons, фотографии и дополнительные версии логотипов. Каждый файл зарегистрирован в [реестре](../../design/assets/manifest.json) с исходником, контрольной суммой и преобразованием.

- Шесть словесных логотипов переведены в настоящие контуры Unbounded 500 с формированием глифов HarfBuzz. Не зависят от шрифта на устройстве.
- Три версии знака `mark-*-ui.svg` имеют плотный viewBox для точного размера в шапке; геометрия кольца и точки сохранена. Область маски задана явно, белая версия прозрачна.
- Исходные SVG сохранены рядом; изменённые производные не несут старую подписанную метаинформацию оригинала.
- Локальные Onest и Unbounded, лицензии OFL и адреса загрузки с SHA-256 находятся в [design/fonts](../../design/fonts/sources.json). В проекте используются Onest 400/500 и Unbounded 500.
- Фото и графика из пользовательского экспорта используются как предоставленные материалы. Подтверждения прав на публичную публикацию фото в исходниках нет; статус явно записан, новые права не предполагаются.
- Нативные варианты app icon сохранены как SVG-исходники. PNG-экспорты для магазинов приложений и проверка актуальных нативных требований не входят в браузерный этап.

Для повторной сборки нужен Python с `lxml`, `fonttools`, `uharfbuzz`:

```bash
python3 scripts/build_brand.py
python3 scripts/validate_brand.py
```

Скрипт читает неизменённые источники, применяет явно заданные переопределения и пересобирает JSON/CSS, ассеты и девять эталонных кадров. Полный набор ассетов и шрифтов уже сохранён: установка этих библиотек для просмотра брендбука не нужна.

Брендбук продолжает дополняться вместе с приложением. Базовый UI kit, вход и онбординг готовы; первый путь бронирования описан в ../iteration-4/README.md. Полный прототип ещё в разработке.

D-010: в рабочем эталоне a1 убраны синяя рамка и свечение поля телефона; архив сохранён. Мобильная оболочка и базовый UI kit готовы: ../iteration-3/README.md. Поиск и бронь реализованы в объёме первого сквозного пути итерации 4.

## Синхронизация с приложением

В версии 1.1 убраны устаревшие 2 секунды заставки и отдельная демонстрация знака с таймингом 400 мс. D-011: заставка 2400 мс, прозрачность 600 мс, сдвиг 36 px за 800 мс, завершение 1400 мс. Фокус телефона нейтральный по D-010. В разделе motion — 23 поведения из исходников с явным статусом каждого. Кнопки, вкладки, тумблер, тост, счётчик гостей и успех брони реализованы; будущие компоненты не обозначены готовыми.

Шторки, стек экранов и клавиатура используют защищённый mobile runtime с пружиной. Это не заявляется как точное совпадение с целевыми 460/380/340 мс: расхождение явно сохранено в таблице. Изменение runtime — отдельная задача. Архивные экраны сохраняют прежние подписи; актуальная логика определяется решениями пользователя.
